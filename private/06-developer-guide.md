# Developer Guide — Setup, Scripts & Workflow

Everything you need to run, modify, and extend this project.

---

## Prerequisites

- **Node.js 20 or newer** — download from [nodejs.org](https://nodejs.org)
- A **Gemini API key** — free at [aistudio.google.com/apikey](https://aistudio.google.com/apikey) (no credit card needed for the free tier)

---

## Initial Setup

```bash
# 1. Install all dependencies
npm install

# 2. Configure your API key
# Open .env.local in your editor and add:
# GEMINI_API_KEY=your_key_here

# 3. Start the development server
npm run dev
# → Open http://localhost:3000
```

> **Restart required:** After editing `.env.local`, restart `npm run dev` — environment variables are read at startup.

## Environment Variables

Defined in `.env.local` (copy from `.env.example`):

| Variable | Required | Default | Description |
|---|---|---|---|
| `GEMINI_API_KEY` | **Yes** | — | Your Gemini API key |
| `GEMINI_MODEL` | No | `gemini-flash-latest` | Override the model (e.g. `gemini-2.5-pro`) |
| `GEMINI_GROUNDING` | No | `on` | Set to `off` to disable Google Search grounding |

## Key Concepts for Editing

### Adding a new language string

1. Open `lib/i18n.ts`
2. Add the key to the `Strings` interface (TypeScript will show an error until both languages are filled)
3. Add the string to both the `en` object and the `hi` object
4. Use it in a component with `const S = t(lang); S.yourNewKey`

### Updating wage rates

1. Open `lib/knowledge.ts`
2. Update `DELHI_MIN_WAGE.monthly` values and `DELHI_MIN_WAGE.asOf`
3. Update the `source` and `note` fields if needed
4. No restart required (the values are read at request time)

### Adding a new quick-prompt chip

1. Open `lib/i18n.ts`
2. Find `quickPrompts` in both `en` and `hi` objects
3. Add `{ label: "Short button text", prompt: "Full question to send to AI" }`
4. The `QuickChips.tsx` component automatically renders all entries

### Adding a new complaint issue type

1. Open `lib/i18n.ts`
2. Find `issues` in both `en` and `hi` objects
3. Add `{ key: "unique_key", label: "Display label" }`
4. Open `components/ComplaintModal.tsx`
5. Add the English description to `ISSUE_EN` object: `unique_key: "Full English description for the AI"`

### Adding a new API route

1. Create `app/api/your-route/route.ts`
2. Export a `POST` (or `GET`) async function
3. Add `export const runtime = "nodejs";` at the top
4. Call `getClient()` from `lib/gemini.ts` to get the Gemini client

### Modifying the AI's behaviour

1. Edit `lib/systemPrompt.ts` — change `buildSystemPrompt()` for chat, `buildComplaintSystemPrompt()` for complaints
2. OR run `npm run ralph` to let the AI improve itself based on failing test cases
3. The `evals/prompt.override.md` file (auto-generated by Ralph) is appended to the system prompt at runtime — edit it directly for quick guardrail adjustments

## Deploying to Vercel (Free)

1. Push the repo to GitHub
2. Go to [vercel.com](https://vercel.com) → Import Project → select your repo
3. In Project Settings → Environment Variables, add `GEMINI_API_KEY`
4. Deploy — Vercel auto-builds and gives you a public URL
5. Any `git push` to the main branch auto-redeploys

## TypeScript Path Aliases

`tsconfig.json` configures `@/` as an alias for the project root. So:
```typescript
import { t } from "@/lib/i18n";
// is the same as:
import { t } from "../../lib/i18n";
```

This keeps imports clean regardless of how deeply nested a file is.

## How `"use client"` Works

In Next.js App Router, every file is a **Server Component** by default — it runs on the server, never in the browser.

Adding `"use client"` at the top of a file marks it as a **Client Component** — it runs in the browser and can use React hooks (`useState`, `useEffect`), browser APIs (`fetch`, `localStorage`, `document`), and event handlers.

**Server Components** in this project:
- `app/layout.tsx` — just renders HTML structure
- `app/api/*/route.ts` — server-only API code

**Client Components** (with `"use client"`):
- `app/page.tsx` — needs `useState` for modal/language state
- All `components/*.tsx` — need event handlers, hooks
- `lib/useChat.ts` — uses `useState`, `useRef`, `useCallback`

## Common Issues

**"The assistant is not configured yet"**
→ Add `GEMINI_API_KEY=...` to `.env.local` and restart `npm run dev`

**Hindi font not loading**
→ The Noto Devanagari font loads via Google Fonts at startup. Check your internet connection.

**Grounding 429 error in logs**
→ Your API key doesn't have billing. The app falls back automatically. Set `GEMINI_GROUNDING=off` in `.env.local` to skip the failed attempt and go straight to fallback mode.

**Complaint generation fails**
→ The complaint endpoint uses a `responseSchema`. Some older model versions don't support it. Check `npm run probe` to see what your key supports.
